## 二、项目是什么

自托管的本地文件处理工具站。核心卖点：**文件全程本机处理，不上传第三方**。前端是纯静态 SPA（由后端直接托管），后端 FastAPI + Pydantic v2，两者靠一套显式契约对接。

| 维度 | 数据 |
|------|------|
| 技术栈 | Python 3.13 / FastAPI 0.141 / Pydantic 2.13 / Starlette / SQLite；前端原生 JS（无框架、无构建） |
| 后端代码 | 63 个 `.py`，**22,241 行** |
| 前端代码 | 46 个文件（js/css/html），**25,476 行**（不含 `vendor/` 第三方） |
| 测试代码 | 12 个文件，**5,524 行**，**201 个用例** |
| 自有代码合计 | **约 5.3 万行** |
| HTTP/WS 端点 | **41 个**（40 个 HTTP + 1 个 WebSocket） |
| 依赖策略 | 核心 6 个（服务可启动）/ 全量 17 个（功能全开）→ 缺引擎时降级为 503 而非崩溃 |

## 五、本机运行环境现状（与线上对照见 §10）

> 本节全部指**开发机**（`C:\Users\admin\Desktop\万能软件包`）。服务器上的引擎与依赖是齐的（3/4 引擎、17/17 依赖），两套环境差异很大。

### 5.1 外部引擎：本机 4/4 全部缺失

实跑 `engine_probe.probe()` 的结果：

| 引擎 | 状态 | 影响 |
|------|------|------|
| LibreOffice | ❌ `fail` | Office ⇄ PDF、Office 互转、Office→图片 全部不可用（矩阵里最大的一块） |
| Chromium | ❌ `fail` | HTML→PDF/PNG、Markdown 导出 PDF 不可用 |
| FFmpeg | ❌ `fail` | 音频转码、B站 DASH 合并、仅音频 mp3 全部不可用 |
| yt-dlp | ❌ `fail` | 视频解析最后一级兜底缺失（不影响三平台主链路） |

`runtime/` 目录为**空**——项目设计上支持三种引擎查找方式（runtime 目录 / 绝对路径 / PATH），当前三种都落空。

### 5.2 Python 依赖：6 / 17

`.venv` 里只有 35 个包，对应依赖清单如下：

| 已装 ✅ | 缺失 ❌ |
|---------|---------|
| fastapi、uvicorn、pydantic、pypdf、openpyxl、python-multipart（+ pytest/ruff/httpx） | **PyMuPDF、pdf2docx、pdfminer.six、pdfplumber、python-docx、python-pptx、mammoth、mutagen、paramiko、cryptography、playwright** |

**直接后果（按模块）**：
- PDF 工具集（合并/拆分/旋转/加密）→ ✅ 可用（pypdf）
- PDF→图片 / PDF→PPTX → ❌ 需 PyMuPDF
- PDF→DOCX / PDF→XLSX → ❌ 需 pdf2docx / pdfplumber
- DOCX/PPTX→任意 → ❌ 需 python-docx / python-pptx / mammoth
- SSH 终端 → ❌ 需 paramiko（模块开着但连不上）
- 音频标签读写 → ❌ 需 mutagen
- Cookie 加密 → ⚠️ 自动降级为 HMAC 流加密（代码有分支，安全但非 AES-GCM）

### 5.3 环境层面的一个坑（本次踩到）

`.venv/Scripts/python.exe` 在 **Git Bash** 下无法启动：

```
failed to open 'C:\Users\admin\Desktop\?????\.venv\pyvenv.cfg'
```

原因是项目路径含中文（`万能软件包`），Git Bash 传给子进程的 `argv[0]` 被按 ANSI 编码降级，`python.exe` 定位不到自己的 `pyvenv.cfg`。**不是 venv 坏了**——用 `cmd` / `start.bat` / PowerShell 正常。本次分析用「托管解释器 + `PYTHONPATH` 指向 venv 的 site-packages」绕过。

> 建议：长期方案是把项目移到纯 ASCII 路径（如 `C:\toolkit`）。这类问题会在 PyInstaller 打包、子进程调用、日志路径上反复出现。

## 七、已经解决的关键问题（说明工程深度，不是"能跑就行"）

按价值排序，这些是项目里真正有分量的部分：

1. **视频下载 `format_id` 撞车（生产环境复现后修复）** — B站用「高度反查 qn」生成 `format_id`，老视频 384p DASH 反查失败后退回 `entry["id"]`，与 480P 占位项撞车；同 qn 的 AVC/HEVC/AV1 三路编码也共用同一 id。结果是下载器拿到空 URL，报 `DOWNLOAD_FAILED` 或误报 `LOGIN_REQUIRED`。改为 `dash-{qn}-{codecid}` 唯一命名 + 新增 `formats[].available` 契约字段 + `default_format_id`。
2. **SSRF 逐跳校验** — 短链跳转每一跳都重新校验白名单，拒绝回环/内网/云元数据地址，且测试断言"出站请求计数为 0"，证明拦截发生在发请求之前。
3. **登录门禁三重防护** — HTML 首帧 `data-app-gate="locked"`（不闪面板）+ 前端确认登录态前不建路由/不拉数据 + 后端全 `/api/*` 401。
4. **凭据不落盘** — SSH 密码/私钥只活在内存保险箱；平台 Cookie 写盘即加密，接口只回显 `SESSDATA=****9f2a`。
5. **缺引擎优雅降级** — 只装 6 个核心依赖时服务照常起，缺的功能返回带安装指引的 503。这是让"199 项测试在无引擎环境全绿"的前提。
6. **超管带外救援** — `config.toml` 里的超级管理员不落库，数据库损坏时仍能登录；配 `scripts/reset_admin.py` 五条子命令。
7. **协作式任务取消** — 不用 `future.result(timeout=)`（那样线程还在跑并占槽位），改用取消标记 + 检查点自查退出。

- **`[video] enabled = true` 且站点公网可达** → 整站等于一个开放的平台下载代理。自用请改 `false`，或给 `/api/video/*` 加 IP 白名单
- `auth_required` 线上已是 `true`（`/healthz` 实测），这条无风险

### 第 2 步：把本机环境补上（1–2 小时）

线上什么都不缺，缺的是本机这套开发环境（引擎 0/4、依赖 6/17）。想让本地能复现与联调：

```bash

# 3) Chromium：pip install playwright && playwright install chromium

```

### 第 3 步：清掉配置漂移（半天）

1. **引擎路径写的与实际不符**：线上 `config.toml` 写 `runtime/libreoffice/program/soffice`（该目录为空），实际靠 PATH 兜底找到 `/usr/bin/soffice`。能跑，但哪天 PATH 变了就静默失效。建议改写实际路径（`/usr/bin/soffice`、`/usr/bin/ffmpeg`、`/root/.cache/ms-playwright/...`）

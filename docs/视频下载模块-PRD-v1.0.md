## 1. 背景与目标

### 1.1 现状与问题

全能工具站目前已有 4 个业务模块：**转换中心**（23 条 Office/PDF/图片转换路径）、**SSH 终端**、**音频处理**（NCM 解封装 + 转码）、**Markdown 导出**。它们的共同前提是「用户手里已经有文件」。

但在实际使用中，用户最高频的诉求是「先把内容拿到手」：

| 用户痛点 | 现状 | 后果 |
|----------|------|------|
| 抖音作品想留存 | 只能用 App 内「保存本地」，带平台水印、画质被压 | 素材不可直接二次使用 |
| B站视频想离线看 | 客户端缓存加密，无法导出 mp4 | 换设备/剪辑时无法使用 |
| 快手作品要归档 | 无桌面端保存能力 | 只能录屏，画质损失严重 |
| 多平台素材收集 | 需要在 3 个 App、多个第三方解析站之间来回切换 | 效率低、广告多、链接隐私外泄 |
| 下载中断 | 第三方站刷新即失效、不支持断点续传 | 大文件反复重下 |
| 下载后处理 | 下载完还要再上传到转换/音频模块 | 多一次上传，浪费带宽与时间 |

### 1.2 产品定位

> **一条链接，一次粘贴，三平台统一解析；下载交给后台任务中心，产物与其它模块共用同一套文件与 TTL 体系。**

差异化不在「能下载」（第三方站也能），而在：

1. **自托管、无广告、链接不外泄**——解析全部在本机/内网服务完成；
2. **任务化**——断点续传、进度可见、可取消、失败可重试，而非一个会中断的浏览器下载；
3. **闭环**——下载产物可直接进入转换中心/音频模块做后续处理，不再二次上传；
4. **可插拔**——平台接口变更只影响对应适配器，不影响其它平台与整体可用性。

### 1.3 建设目标

| 维度 | 目标 | 衡量方式 |
|------|------|----------|
| 用户效率 | 从「复制链接」到「拿到文件」≤ 3 次操作 | 交互走查 |
| 解析能力 | 公开作品解析成功率 ≥ 95% | 300 条真实样本回归 |
| 下载体验 | 3 分钟内 1080P 视频端到端 P95 ≤ 90 秒（本机 10 Mbps 以上） | 压测 + 埋点 |
| 稳定性 | 单平台接口异常时，其它平台可用性不受影响 | 故障演练 |
| 可维护性 | 新增 1 个平台 ≤ 2 人日，且不改动路由与前端核心逻辑 | 适配器接口评审 |

### 1.4 非目标（明确不做）

需求边界必须写死，否则排期与合规都会失控。

| 编号 | 不做的事 | 原因 |
|------|----------|------|
| NG-01 | 直播流 / 直播回放录制 | 实时性与资源模型完全不同，且平台风控更严 |
| NG-02 | 付费内容、会员专属画质、付费课程 | 绕过付费墙属明确侵权，触碰法律红线 |
| NG-03 | DRM / 加密媒体的解密 | 与现有音频模块的 `DRM_PROTECTED` 红线保持一致 |
| NG-04 | 站点级爬虫、按作者/话题/榜单批量采集 | 违背平台协议，且会把工具站变成采集器 |
| NG-05 | 多账号池、Cookie 共享/租借 | 账号安全与合规风险，且属于对抗平台风控 |
| NG-06 | 下载后自动发布、搬运、去重改码 | 侵权链条的关键环节，坚决不做 |
| NG-07 | 自研「去水印算法」 | 只使用平台对外提供的播放地址；拿不到无水印版本就如实告知 |
| NG-08 | 原生 App（iOS/Android） | V1.0 仅 Web；移动端走浏览器自适应 |
| NG-09 | 弹幕、字幕、评论抓取 | 非核心诉求，V1.0 不做（字幕列为 V1.1 候选） |
| NG-10 | 通用 yt-dlp 全站支持（1000+ 站点） | 仅支持本文档列明的 3 个平台，避免合规面失控 |

### 1.5 成功指标

| 指标 | 定义 | V1.0 目标 |
|------|------|-----------|
| 首次解析成功率 | 首次粘贴即返回可用 `formats` 的比例 | ≥ 95% |
| 任务成功率 | `status=success` 的任务占比 | ≥ 95% |
| 端到端耗时 P95 | 提交到产物可下载 | ≤ 90 秒（≤3 分钟 1080P） |
| 失败可解释率 | 失败任务带明确 `error_code` 且文案可读 | 100% |
| 重复下载命中率 | 24 小时内重复作品直接复用产物的比例 | ≥ 25% |
| 服务端错误率 | 5xx 响应占比 | ≤ 0.5% |
| 页面操作步数 | 粘贴 → 点击下载 → 取文件 | ≤ 3 步 |

### 2.3 核心用户旅程

主流程（Happy Path）：

```text
[在抖音/B站/快手 App 复制分享链接]
              |
              v
[打开工具站 -> 视频下载页]
              |
              v
[粘贴(或点粘贴按钮/回车)] --自动去抖 300ms--> [POST /api/video/parse]
              |
      +-------+--------+
      |                |
   解析成功          解析失败
      |                |
[结果卡片:封面/标题/  [写明原因:
 作者/时长/清晰度]     作品已删除/需登录/
      |                链接不支持]
[选清晰度 -> 点击下载]
      |
[POST /api/video/download -> 返回 task]
      |
[任务中心轮询 1s -> 进度条]
      |
[success -> 下载产物 / 批量打包 zip]
```

异常与分支流程：

```text
短链展开失败      -> SHORTLINK_EXPAND_FAILED，提示"链接已失效或需要更换网络"
区域/风控拦截     -> RISK_CONTROL，提示"平台风控中，已暂停该平台 10 分钟"
需要登录          -> LOGIN_REQUIRED，引导到设置页录入 Cookie，可降级下载 720P
Cookie 过期       -> COOKIE_INVALID，脱敏提示 + 一键跳转更新
任务中断/重试     -> 自动重试 2 次，仍失败则保留可重试按钮
用户取消          -> 停止分片下载，删除半成品，任务置 cancelled
```

### 4.2 FR-VD-01 链接输入与识别

**描述**：用户在输入框中粘贴任意内容（纯链接、分享文案、多行混合），系统提取其中的作品链接并交给解析。

**规则**：
1. 输入框支持：单行粘贴、多行文本、粘贴分享文案（含中文、表情、`$` 等符号）。
2. 提取规则：用 `https?://[^\s"'<>（）()]+` 提取候选链接；去掉尾部中文标点；最多保留 20 条。
3. 去重：同一批次内相同 URL 去重；短链与长链视为不同（在解析后按 `platform+item_id` 二次去重）。
4. 触发方式：
   - 粘贴后**不自动提交**，需按回车或点「解析」按钮（避免误触发限流）；
   - 前端做 300ms 防抖；
   - 输入为空时不发请求。
5. 前端预校验：非白名单域名直接提示「暂不支持该平台」，不消耗服务端配额。
6. 剪贴板：仅在用户点击「粘贴」按钮时调用 `navigator.clipboard.readText()`；**不做**后台剪贴板监听（隐私红线）。
7. HTTPS 与 HTTP 均可识别，`http://` 归一化为 `https://`。
8. 移动端分享到浏览器时，允许通过 URL 参数 `?url=` 预填（便于后续做分享直达）。

**异常处理**：

| 场景 | 提示文案 |
|------|----------|
| 没有识别到链接 | 没有识别到作品链接，请粘贴完整分享文案或链接 |
| 超过 20 条 | 单次最多解析 20 条链接，当前 N 条 |
| 域名不支持 | 暂不支持该平台，当前支持抖音、B站、快手 |
| 作品已删除/私密 | 作品不存在或已被作者删除/设为私密 |

**验收要点**：
- 粘贴「7.43 复制打开抖音，看看【某某】的作品 https://v.douyin.com/xxxx/ 」能正确提取链接；
- 一条失败不影响同批次其它链接（逐条返回，呼应音频探测模块的教训）；
- 20 条以上被前端拦截且不消耗服务端限流配额。

### 4.3 FR-VD-02 平台适配与短链展开

**描述**：按域名路由到对应适配器；短链先展开为长链再解析。

**规则**：
1. **域名白名单**（唯一可信来源，硬编码于 `adapters/registry.py`，并允许 config 追加）：

   | 平台 | 允许的 host |
   |------|-------------|
   | 抖音 | `douyin.com`、`www.douyin.com`、`v.douyin.com`、`iesdouyin.com`、`www.iesdouyin.com` |
   | B站 | `bilibili.com`、`www.bilibili.com`、`m.bilibili.com`、`b23.tv` |
   | 快手 | `kuaishou.com`、`www.kuaishou.com`、`v.kuaishou.com`、`m.kuaishou.com` |

2. **SSRF 防护（强制）**：
   - 只允许 `https`；
   - 展开短链时最多跟随 **5 跳**，每跳后重新校验 host 是否在白名单；
   - 解析阶段禁止请求内网/回环/元数据地址（若最终跳转到非白名单，直接失败）；
   - 不复用用户可控的 Header，不跟随 `file://`、`ftp://`。
3. 短链展开超时 5 秒，失败重试 1 次（退避 1 秒），仍失败返回 `SHORTLINK_EXPAND_FAILED`。
4. 适配器统一接口（后端内部契约）：

```python
class PlatformAdapter(Protocol):
    name: str
    hosts: tuple[str, ...]
    def match(self, url: str) -> bool: ...
    def normalize(self, url: str) -> str: ...          # 短链展开 + 去跟踪参数
    def parse(self, url: str, ctx: ParseContext) -> VideoItem: ...
```

5. 新增平台只允许新增 `adapters/xxx.py` 并注册，**不得**修改路由与前端核心逻辑。

**验收要点**：
- 三平台短链各 3 条样例均能正确展开；
- 构造跳转到 `http://127.0.0.1:5000/api/...` 的恶意短链，必须被拒绝（返回 `PLATFORM_UNSUPPORTED` 或 `SHORTLINK_EXPAND_FAILED`，且不发请求）；
- 展开失败时错误码明确，不出现 500。

### 4.4 FR-VD-03 解析与元数据展示

**描述**：返回作品结构化信息，供用户确认并选择清晰度。解析**不下载媒体文件**。

**返回字段**（`VideoItem`）：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `platform` | string | ✅ | `douyin` / `bilibili` / `kuaishou` |
| `item_id` | string | ✅ | 平台内唯一 ID（去重键） |
| `url` | string | ✅ | 归一化后的长链 |
| `media_type` | string | ✅ | `video` / `image` / `mix` |
| `title` | string | ✅ | 作品标题/文案首行，≤200 字 |
| `description` | string | ❌ | 完整文案，≤2000 字 |
| `author` | object | ✅ | `{name, id, avatar_url}` |
| `cover_url` | string | ✅ | 封面地址（可能有时效） |
| `duration_sec` | int | ✅ | 视频时长（图文为 0） |
| `published_at` | string | ❌ | ISO 8601 |
| `stats` | object | ❌ | `{like, comment, share, play}`，可能为空 |
| `formats` | array | ✅ | 清晰度列表，见下 |
| `images` | array | ❌ | 图文作品的图片列表 `[{url, width, height}]` |
| `bgm` | object | ❌ | `{title, author, url}`（P2） |
| `piece_count` | int | ❌ | 多P/合集集数 |
| `parse_source` | string | ❌ | `api` / `html` / `ytdlp`（用于排障，前端不展示） |

**`VideoFormat` 字段**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `format_id` | string | 平台原始格式标识，下载时原样回传 |
| `quality` | string | 归一化等级：`4K`/`2K`/`1080P60`/`1080P`/`720P`/`540P`/`480P`/`360P`/`audio` |
| `width` / `height` | int | 像素尺寸 |
| `fps` | int | 帧率 |
| `bitrate` | int | 码率（bps，可空） |
| `container` | string | `mp4` / `m4a` / `webm` |
| `size_bytes` | int | 预估体积（码率 × 时长，可能为 null） |
| `need_login` | bool | 是否需要登录态 |
| `need_vip` | bool | 是否会员专属（**仅展示，不下载**） |
| `expire_at` | string | 媒体地址过期时间（提醒用户尽快下载） |

**规则**：
1. 解析耗时目标 P95 ≤ 3 秒（不含短链跳转；含跳转 ≤ 5 秒）。
2. 同一 URL 的解析结果缓存 **10 分钟**（内存缓存，键为 `platform+item_id`），避免用户反复点解析触发风控。
3. 解析接口**无副作用**：不落盘、不写历史、不占任务队列。
4. 图文作品：返回 `images` 列表，`formats` 为空；下载时打包为 zip。
5. 多P/合集：V1.0 只解析当前 P（URL 带 `?p=N` 时解析对应 P），`piece_count` 用于提示「该稿件共 N 个分P」。
6. 会员专属清晰度照实返回，但标记 `need_vip=true`，界面上置灰并提示不可下载。

**验收要点**：
- 三平台各 10 条公开视频，字段完整率 100%；
- 同 URL 连续解析 5 次，第 2–5 次命中缓存（日志可见）；
- 图文作品能返回图片数与首图；
- 会员清晰度不出现「可下载」状态。

### 4.5 FR-VD-04 清晰度与输出格式

**规则**：

1. **归一化映射**（各平台原始标识 → 统一等级）：

   | 统一等级 | 抖音 | B站 | 快手 |
   |----------|------|-----|------|
   | 4K | — | 8K/4K（会员） | — |
   | 2K | 2K | 2K | 2K |
   | 1080P60 | — | 1080P60 | — |
   | 1080P | 1080P | 1080P | 1080P |
   | 720P | 720P | 720P | 720P |
   | 540P / 480P / 360P | 540P | 480P/360P | 540P |
   | audio | 仅音频 | 仅音频（dash） | 仅音频 |

2. **默认选择策略**（按顺序命中）：
   - 用户设置的「默认清晰度」若可用 → 用它；
   - 否则取 **≤1080P 的最高可用**；
   - **不默认选 4K**（体积过大，且多为会员专属）；
   - 无登录态时若最高仅 720P，展示提示条「登录 B站账号可下载 1080P 高码率」。

3. **输出容器**：
   - 视频默认 `mp4`（H.264 + AAC），保证兼容性；平台仅提供 DASH 分离流时，由 FFmpeg 合并（复用现有引擎探测）。
   - 仅音频：`mp3`（默认，128 kbps）或 `m4a`（原音轨直通，无损转换）。
   - 图文：`zip`（图片按 `01.jpg` 顺序命名）。

4. **体积预估**：`size_bytes` 由码率 × 时长估算，界面显示为「约 128 MB」；未知时显示「体积未知」。

5. **画质提示**：若平台返回的最高画质带水印而低画质不带（或反之），以平台实际返回为准，**由后端在 `formats[].note` 中如实标注**，不承诺「无水印」。

**验收要点**：
- B站无 Cookie 时最高 720P 且提示登录；有有效 Cookie 时可选 1080P；
- 仅音频导出能产出可播放 mp3；
- 4K 默认不被选中。

### 4.6 FR-VD-05 下载任务与调度

**描述**：下载是异步任务，统一进入现有任务中心，前端轮询 1 秒刷新。

**规则**：

1. 任务模型扩展：`module="video"`，`operation="download"`，`inputs` 需新增可选字段 `source`（见 8.2）。
2. 提交接口返回**任务数组**（支持批量），与音频模块 `POST /api/audio/convert` 行为一致。
3. **进度分段**（单调递增，不可回退）：

   | 进度 | 阶段 | 说明 |
   |------|------|------|
   | 1–5% | 准备 | 复用解析缓存，确定最终媒体地址 |
   | 5–15% | 连接 | 建立连接、读取 `Content-Length` |
   | 15–90% | 下载 | 按已下载字节 / 总字节映射 |
   | 90–98% | 合并封装 | FFmpeg 合并音视频 / 转封装 |
   | 98–100% | 登记产物 | 移动出临时目录、登记 file_id |

4. **并发控制**：
   - 全局同时下载任务数默认 **2**（config `[video] max_concurrent`），避免触发平台风控与打满带宽；
   - 单任务内分片并发默认 **4**（config `download_segments`）；
   - 超出并发则排队（任务 `pending`），前端显示排队位置（复用 `queue_position` 语义）。

5. **断点续传**：
   - 使用 HTTP `Range` 分片下载，每片大小默认 2 MB；
   - 分片级失败重试 **3 次**（指数退避 0.5s/1s/2s）；
   - 任务级失败自动重试 **2 次**；
   - 服务重启后，未完成任务的临时分片文件保留 24 小时，可由用户点「重试」续传；无法续传则从头开始并提示。

6. **取消**：协作式取消（复用 `JobContext.cancelled`），在分片边界检查；取消后删除临时文件，任务置 `cancelled`。
7. **超时**：单任务默认 **600 秒**（config `task_timeout_sec_video`），超时置 `TASK_TIMEOUT` 并清理临时文件。
8. **大小保护**：单文件上限默认 **2 GB**（config `max_file_mb`），超过则任务失败 `OUTPUT_TOO_LARGE`，避免磁盘打满。
9. **磁盘保护**：提交前检查可用空间，低于 `min_free_gb`（默认 2 GB）时拒绝提交，返回 507 或 429 并提示。
10. **任务产物**：成功后 `output.file_id` 可下载；`expire_at` 沿用产物 TTL（默认 24 小时）。

**验收要点**：
- 批量提交 5 条 → 5 个任务，排队与执行符合并发配置；
- 下载中取消，临时目录无残留（存储巡检 uploads/temp 归零）；
- 断网 10 秒再恢复，任务自动重试后成功；
- 服务重启后未完成任务被标记 `INTERRUPTED`（沿用现有机制）。

### 4.7 FR-VD-06 产物命名、打包与存储

**规则**：

1. 命名模板：`{platform}-{author}-{title}-{quality}.{ext}`，例如
   `douyin-某某-晚风里的一百种蓝-1080P.mp4`。
2. 清洗规则：
   - 去除 Windows 非法字符 `\ / : * ? " < > |` 与控制字符；
   - 连续空白压缩为一个空格；
   - 长度截断 **120 字符**（含扩展名），超长时对标题部分截断并保留尾部；
   - 作者名为空时用 `未知作者`，标题为空时用 `未命名作品`。
3. 重名：同目录已存在时追加 `-1`、`-2`（不覆盖用户已有文件）。
4. 批量打包：勾选多个成功任务 → 复用 `POST /api/convert/batch-zip`（需确认该端点按 `task_id` 查任务，支持 `module=video`）；包内保留清洗后的文件名。
5. 存储：下载临时文件在 `storage/temp/video-*/`，成功后 `stage_output()` 移入产物区；任务结束（成功/失败/取消）后删除临时目录。
6. TTL：沿用 `output_ttl_hours`（默认 24 小时），由现有清理线程回收。

**验收要点**：
- 含 `:`、`/`、emoji 的标题能正常落盘；
- 同名两次下载产生 `-1` 后缀；
- 产物过期后下载返回 404 且文案可读。

### 4.8 FR-VD-07 历史记录与去重

**规则**：

1. 历史记录保留最近 **200 条**（可配置），字段：`platform`、`item_id`、`title`、`author`、`cover_url`、`quality`、`size_bytes`、`created_at`、`status`、`task_id`（若有）。
2. **不保存**媒体直链（会过期），只保存 `url` 与 `file_id`。
3. 去重与秒下：
   - 去重键 `platform + item_id`；
   - 若 24 小时内存在 `status=success` 且产物未过期的记录，再次下载时**直接返回该产物**（新建任务但秒完成，或直接返回 `file_id`），不重复请求平台；
   - 命中时前端提示「已为你复用 2 小时前的下载」。
4. 解析缓存命中与产物复用是两件事：解析缓存只复用元数据（10 分钟），产物复用是 24 小时。
5. 历史支持按平台筛选、按标题搜索；支持单条删除与清空。
6. 多用户部署时，历史记录按 `user_id` 隔离（V1.0 单管理员模式可全局共享，但数据结构预留 `owner_id`）。

**验收要点**：
- 同一链接 2 小时内下载两次，第二次秒回且有提示；
- 产物过期后再次下载，任务重新执行而非报错；
- 历史记录不含 `https://...&sign=...` 之类会过期的直链。

### 4.9 FR-VD-08 登录态（Cookie）管理

**背景**：B站 1080P 及以上、部分抖音/快手作品需要登录态；无 Cookie 时只能拿到 720P 或直接失败。

**规则**：

1. 设置页提供三个平台的 Cookie 输入框（B站为 `SESSDATA`，抖音/快手为完整 Cookie 串）。
2. 存储：使用现有 `security` 的凭据保险箱（AES-GCM），落盘 `storage/credentials.json`；**禁止**明文写日志、禁止在接口响应中回显。
3. 回显脱敏：列表接口只返回 `{"platform":"bilibili","configured":true,"masked":"SESSDATA=****9f2a","updated_at":...}`。
4. 有效性检测：保存时做一次轻量校验（请求用户信息接口），失败则 `COOKIE_INVALID`，但仍允许保存并提示。
5. 使用范围：仅用于解析与下载请求；不外传、不用于其它平台。
6. 失效降级：解析时若检测到未登录/失效，仍尽量返回可用低画质，并在响应中带 `warnings: ["LOGIN_REQUIRED"]`，前端展示提示条而非直接失败。
7. 合规提示：界面注明「请使用你本人账号的 Cookie，共享/租借账号违反平台协议」。

**验收要点**：
- 保存 Cookie 后接口只返回脱敏串；
- 故意填错 Cookie，解析降级到 720P 并提示，不 500；
- 日志中搜索不到明文 Cookie。

### 4.10 FR-VD-09 设置项

| 设置项 | 键 | 默认值 | 说明 |
|--------|----|--------|------|
| 默认清晰度 | `prefer_quality` | `1080P` | 可选 4K/1080P/720P/480P |
| 默认输出 | `prefer_format` | `mp4` | mp4 / mp3 / m4a |
| 同时下载数 | `max_concurrent` | 2 | 1–4 |
| 分片并发 | `download_segments` | 4 | 1–8 |

| 任务超时 | `task_timeout_sec_video` | 600 | 秒 |
| 解析缓存 TTL | `parse_cache_ttl_sec` | 600 | 秒 |

### 4.11 FR-VD-10 异常、降级与错误码

**统一错误体**（沿用现有约定）：`{"detail": "<用户可读中文>", "code": "<机器可读>"}`。

| 错误码 | HTTP | 用户文案 | 触发场景 | 处置建议 |
|--------|------|----------|----------|----------|
| `LINK_UNRECOGNIZED` | 400 | 没有识别到作品链接 | 输入无 URL | 提示粘贴完整分享文案 |
| `PLATFORM_UNSUPPORTED` | 400 | 暂不支持该平台 | 域名不在白名单 | 展示支持平台 |
| `URL_BLOCKED` | 400 | 该链接地址不被允许 | SSRF 校验命中 | 不重试，记审计 |
| `SHORTLINK_EXPAND_FAILED` | 502 | 短链已失效，请重新复制 | 跳转失败/超 5 跳 | 请用户重新复制 |
| `PARSE_FAILED` | 422 | 解析失败，平台可能已调整接口 | 页面结构变化 | 记日志，提示稍后重试 |
| `ITEM_NOT_FOUND` | 404 | 作品不存在或已删除 | 404/私密/审核中 | 不重试 |
| `LOGIN_REQUIRED` | 401 | 该清晰度需要登录，当前仅可下载 720P | 未配置 Cookie | 跳设置页；允许降级 |
| `COOKIE_INVALID` | 401 | 登录信息已失效，请重新填写 | Cookie 过期 | 跳设置页 |
| `VIP_REQUIRED` | 403 | 该清晰度为会员专属，暂不支持 | `need_vip` | 置灰，不下载 |
| `REGION_LOCKED` | 403 | 该作品在服务端所在地区不可用 | 地区限制 | 不重试 |
| `RISK_CONTROL` | 429 | 平台风控中，请 10 分钟后再试 | 连续被拦截 | 平台级熔断 10 分钟 |
| `RATE_LIMITED` | 429 | 操作太频繁，请 N 秒后再试 | 本服务限流 | 带 `retry_after` |
| `QUEUE_FULL` | 429 | 任务已满，请稍后再试 | 队列上限 | 沿用现有错误 |
| `DOWNLOAD_FAILED` | 502 | 下载中断，已重试 N 次 | 网络/分片失败 | 提供重试按钮 |
| `OUTPUT_TOO_LARGE` | 413 | 文件超过上限（2 GB） | 超 `max_file_mb` | 建议降清晰度 |
| `DISK_FULL` | 507 | 磁盘空间不足 | 可用空间 < 阈值 | 提示清理 |
| `ENGINE_UNAVAILABLE` | 503 | 缺少合并工具，请安装 FFmpeg | FFmpeg 缺失 | 附安装指引 |
| `TASK_TIMEOUT` | 422 | 下载超时 | 超过 600s | 可重试 |
| `INTERRUPTED` | — | 服务重启导致任务中断 | 重启 | 可重试 |

**降级链**（按顺序尝试，任一成功即停）：

```text
平台公开接口(首选)
      |
      v
平台分享页 HTML 解析
      |
      v
yt-dlp 引擎(可选安装)
      |
      v
失败: 返回明确错误码(不返回空结果)
```

**规则**：所有失败必须带 `error_code`，禁止出现「未知错误」；后端 `describe_exception` 兜底文案需补充视频场景。

### 4.12 FR-VD-11 审计、限流与熔断

1. **审计日志**：每次下载写 `storage/audit.log`，字段：`action=video.download`、`ip`、`platform`、`item_id`（SHA256 前 8 位）、`quality`、`size`、`result`、`error_code`。不记录完整 URL（可能含跟踪参数）与 Cookie。
2. **限流**（按用户 + IP 双维度）：
   - 解析：20 次/分钟，100 次/小时；
   - 下载：10 次/分钟，50 次/小时；
   - 超限返回 429 + `retry_after`（复用 `RateLimitedError`）。
3. **平台级熔断**：
   - 同一平台连续 5 次出现 `RISK_CONTROL` / `PARSE_FAILED` → 该平台冷却 **10 分钟**，期间提交直接返回 `RISK_CONTROL` 并提示；
   - 冷却状态在「系统状态」页可查看，管理员可手动解除（P2）。
4. **总开关**：`[video] enabled=false` 时所有 `/api/video/*` 返回 503 `SERVICE_DISABLED`（与 SSH 模块未启用的语义一致）。

## 5. 非功能需求

### 5.1 性能

| 编号 | 要求 |
|------|------|
| NFR-VD-P01 | 解析接口 P95 ≤ 3 秒（含短链跳转 ≤ 5 秒），P99 ≤ 8 秒 |
| NFR-VD-P02 | 1080P、3 分钟视频（约 60 MB）端到端 P95 ≤ 90 秒（≥10 Mbps 环境） |
| NFR-VD-P03 | 下载任务并发默认 2，单任务分片并发 4，可配置上限 8 |
| NFR-VD-P04 | 任务进度刷新间隔 1 秒，前端不因轮询造成明显卡顿（复用现有轮询） |
| NFR-VD-P05 | 解析缓存命中时响应 ≤ 200 ms |

### 5.2 可靠性

| 编号 | 要求 |
|------|------|
| NFR-VD-R01 | 单平台故障不影响其它平台（适配器隔离 + 熔断） |
| NFR-VD-R02 | 下载失败自动重试 2 次，分片重试 3 次；重试仍失败给出明确原因 |
| NFR-VD-R03 | 服务重启后未完成任务标记 `INTERRUPTED`，可手动重试续传 |
| NFR-VD-R04 | 任务目录在成功/失败/取消后均无残留（存储巡检 uploads/temp 归零） |
| NFR-VD-R05 | 磁盘可用空间低于阈值时拒绝新任务，不写坏文件 |

### 5.3 安全

| 编号 | 要求 |
|------|------|
| NFR-VD-S01 | SSRF 防护：域名白名单 + 每跳校验 + 禁止内网/回环/元数据地址 |
| NFR-VD-S02 | 路径穿越防护：产物名经 `safe_filename` 清洗，下载只允许 `file_id` 查表 |
| NFR-VD-S03 | Cookie 加密存储（AES-GCM），接口脱敏，日志脱敏，禁止入 Git |
| NFR-VD-S04 | 越权：任务与产物按 `owner_id` 校验（多用户模式） |
| NFR-VD-S05 | 限流与熔断防止被当作免费代理/采集器 |
| NFR-VD-S06 | 所有 `/api/video/*` 走统一鉴权守卫 `GuardDep`（与其它模块一致） |
| NFR-VD-S07 | 不执行平台返回的任何脚本；HTML 解析使用 BeautifulSoup/lxml，禁用 JS 执行 |

### 5.4 合规

| 编号 | 要求 |
|------|------|
| NFR-VD-C01 | 仅支持用户主动粘贴的单个/少量链接，不提供站内搜索、榜单、爬取入口 |
| NFR-VD-C02 | 不绕过付费墙、会员、DRM、加密 |
| NFR-VD-C03 | 产品内明示「仅供个人学习研究，不得用于商业传播」 |
| NFR-VD-C04 | 接到版权方/平台通知可一键禁用某平台（`platforms.{name}.enabled=false`） |
| NFR-VD-C05 | 产物默认保留 24 小时后自动删除，降低二次传播风险 |

### 5.5 兼容性

| 编号 | 要求 |
|------|------|
| NFR-VD-X01 | 浏览器：Chrome / Edge / Firefox / Safari 最近两个大版本 |
| NFR-VD-X02 | 服务端：Windows 与 Linux 均可运行；不新增必须的系统依赖 |
| NFR-VD-X03 | 移动端：iOS Safari、Android Chrome 可用；微信内置浏览器允许手动粘贴 |
| NFR-VD-X04 | 外部引擎：FFmpeg 可选（缺失时仅影响合并/转音频，返回 503 指引）；yt-dlp 可选 |
| NFR-VD-X05 | 产物编码：H.264 + AAC 的 mp4，Windows 播放器与剪辑软件可直接打开 |

### 5.6 可观测性与可维护性

| 编号 | 要求 |
|------|------|

### 6.4 关键交互规则

1. **粘贴即填充，回车才解析**——避免剪贴板里残留内容自动触发请求（既省配额也更符合预期）。
2. 多行粘贴自动进入批量模式，逐条显示解析状态（解析中/成功/失败），失败项不阻塞其它项。
3. 清晰度下拉默认值来自用户设置；不可用项（需会员/需登录）置灰并附 `title` 说明。
4. 下载按钮点击后立即禁用并显示「已加入任务」，防止重复提交。
5. 解析结果卡片中的封面图使用 `referrerpolicy="no-referrer"`，避免泄露来源页。
6. 任务完成用浏览器通知（可选，需用户授权）或页面内 toast，不做声音提示。
7. 移动端：输入框占满宽度，结果卡片单列，清晰度用底部弹层选择。

### 6.5 移动端适配

- 断点沿用现有 `mobile.css`（≤768px）；
- 批量模式在移动端折叠为「逐条添加」；
- 下载产物在移动端浏览器中通过 `Content-Disposition` 触发系统下载器；
- 微信内置浏览器：WebView 下载可能受限制，提示「请用系统浏览器打开」。

### 6.6 文案规范

- 使用「作品」「清晰度」「产物」等中性词，避免「破解」「去水印」「提取」等敏感表述；
- 失败文案必须包含**原因 + 下一步动作**，例如「作品已被作者删除（ITEM_NOT_FOUND）。请确认链接是否仍可打开」；
- 不承诺平台未提供的能力（如无水印、原画质），使用「以平台提供的最高清晰度为准」。

## 7. API 契约

### 7.1 通用约定（继承现有后端）

| 约定 | 说明 |
|------|------|
| 响应字段 | snake_case（`task_id`、`file_id`、`page_size`） |

### 8.2 任务模型扩展（改动点）

现有 `TaskInput` 只有 `name / size / sha256`，视频任务没有上传文件，需要携带来源 URL：

```python
@dataclass(slots=True)
class TaskInput:
    name: str
    size: int
    sha256: str = ""
    # 新增：远程来源（视频下载用），旧数据缺失时按 None 处理，必须向后兼容
    source: str | None = None

    def to_api(self) -> dict[str, Any]:
        data = {"name": self.name, "size": self.size, "sha256": self.sha256}
        if self.source:
            data["source"] = self.source
        return data
```

`TaskModule` 字面量增加 `"video"`：

```python
TaskModule = Literal["converter", "audio", "markdown", "system", "video"]
```

任务操作标识：`operation="download"`（单个）与 `operation="download_batch"`（批量，可选）。

## 9. 技术方案建议

> 本章为**建议**，实现方可调整；但第 7 章契约与第 10 章红线不可变。

### 9.1 模块结构（与现有分层一致）

```text
app/modules/video/
├─ __init__.py
├─ router.py          # 只做协议转换：参数校验 + 调 service
├─ service.py         # 编排：解析 → 构造任务 → 下载 → 登记产物
├─ history.py         # 历史记录读写（原子写、去重、TTL）
├─ settings.py        # 视频模块设置与 Cookie 脱敏读写
├─ downloader.py      # 分片下载、断点续传、限速、FFmpeg 合并
└─ adapters/
   ├─ base.py         # PlatformAdapter 协议 + VideoItem/VideoFormat 数据类
   ├─ registry.py     # 域名白名单 + 平台注册与路由
   ├─ douyin.py
   ├─ bilibili.py
   ├─ kuaishou.py
   └─ ytdlp.py        # 可选兜底引擎（未安装则跳过）
```

分层纪律：`adapter` 只负责「链接 → 元数据 / 媒体地址」，**不碰任务、不落盘**；`router` 不写业务逻辑；`service` 负责编排与错误码映射。

### 9.2 解析策略与降级链

1. **首选平台公开接口/分享页**：使用普通 HTTP 客户端（httpx/aiohttp）请求分享页或公开接口，从页面内嵌 JSON（如 `window.__INITIAL_STATE__`）或接口响应中提取元数据。
2. **HTML 解析兜底**：结构化数据缺失时退化为解析 `<meta property="og:*">` 与页面 script 中的 JSON 片段。
3. **yt-dlp 可选兜底**：作为独立引擎探测（复用 `core/engines.py` 模式），未安装时直接跳过，不报错；安装后可作为新平台快速接入的通道。
4. **不强制登录**：所有请求先匿名尝试；仅在用户配置了 Cookie 且匿名结果不满足画质需求时才带 Cookie。
5. **超时与重试**：解析请求超时 5 秒，连接类错误重试 1 次；解析结果写内存缓存。
6. **风控应对**：固定 UA 但可配置；不伪造设备指纹；解析与下载分离（解析轻、下载重）；连续失败触发熔断。

### 9.3 下载策略

```text
1. 取 media_url（可能有时效）→ 校验 scheme 为 https、host 属于已知 CDN 白名单
2. HEAD/GET Range: bytes=0-0 获取 Content-Length 与 Accept-Ranges
3. 按 segment_size 分片，线程池并发 4，每片独立重试 3 次
4. 进度 = 已写字节 / 总字节，映射到 15–90%
5. 音视频分离流 → FFmpeg -c copy 合并；否则直接落盘
6. 校验产物：文件存在、大小 > 0、mp4 moov 可解析（ffprobe，缺失则跳过校验）
7. stage_output() 移出临时目录 → registry.register() → 任务 success
```

要点：

- **Range 不可用**（服务器返回 200）时退化为单流下载，进度按字节；
- **地址过期**（403）时重新解析一次再下，仍失败则 `DOWNLOAD_FAILED`；
- **限速可选**：全局令牌桶（默认不限速，带宽紧张时可配）；
- **磁盘检查**：写入前 `shutil.disk_usage` 校验 `min_free_gb`。

## 10. 合规与法律边界

> 本章是**需求的一部分**，不是免责声明。产品形态、接口设计、默认配置都必须体现这些约束。

### 10.1 著作权

1. 视频作品的著作权归原作者/平台所有，本功能仅服务于**个人学习、研究与离线备份**。
2. 产品内必须有明确提示：「下载内容仅供个人使用，请勿用于商业传播或二次分发；由此产生的法律责任由使用者承担」。
3. 产物默认 24 小时自动删除，不提供长期存储与分享链接（分享能力属 `express` 类功能，需单独评估，V1.0 不开放）。
4. 收到版权方或平台的有效通知后，管理员可通过关闭平台开关（`platforms.{name}.enabled=false`）在 1 分钟内下线该平台能力。

### 10.2 平台协议

| 约束 | 落地方式 |
|------|----------|
| 不绕过付费/会员/DRM | `need_vip=true` 的清晰度置灰；无解密逻辑；错误码明确 `VIP_REQUIRED` |
| 不使用非本人账号凭据 | Cookie 仅由用户本人录入，界面明示；不做账号池、不做租借 |
| 不伪造设备指纹/不破解签名 | 只使用普通 HTTP 请求；不集成自动化对抗风控的模块 |
| 不做站点级爬取 | 无搜索、无榜单、无作者主页批量入口；单次 ≤20 条 |
| 控制请求频率 | 解析 20 次/分钟、下载 10 次/分钟、平台熔断 10 分钟 |
| 尊重 robots 与页面声明 | 不抓取明确禁止抓取的路径；以分享页为主 |

### 10.3 个人信息

1. 不建立作者信息库，不持久化作者头像/昵称之外的信息；历史记录仅保留展示所需字段。
2. 日志中 `item_id` 做哈希截断，URL 不入日志，Cookie 全程脱敏。
3. 多用户部署时历史按 `owner_id` 隔离，避免互相看到下载内容。

### 10.4 水印与画质

- 只使用平台对外提供的播放地址；若平台提供的是带水印版本，则**如实呈现**，不实现去水印算法；
- 界面上不出现「无水印下载」承诺，统一表述为「以平台提供的最高清晰度为准」；
- 若平台提供的地址本身不含水印（如部分分享接口），属于平台行为，产品不做额外处理。

### 10.5 部署形态

- 默认仅监听 `127.0.0.1`，或部署在内网 NAS；
- 公网部署时，工具站已强制开启鉴权（`auth_required=true`），且需额外评估平台 ToS 与当地法律；
- 公网部署建议在 README 增加显著风险提示，并默认关闭视频模块（`enabled=false`），由部署者显式开启。

### 10.6 产品内声明（文案草稿）

> 本功能仅用于下载你有权访问的公开作品，供个人学习、研究与离线备份使用。请遵守各平台用户协议与著作权法，勿将下载内容用于商业用途或二次传播。本工具不提供付费内容、会员画质或加密内容的获取能力。

### 15.3 错误码总表

见 4.11。前端分支建议：`LOGIN_REQUIRED` / `COOKIE_INVALID` → 引导设置页；`RISK_CONTROL` / `RATE_LIMITED` → 展示倒计时；`VIP_REQUIRED` → 置灰；其余 → 通用错误卡片 + 重试。

### 15.4 竞品对比

| 方案 | 优点 | 缺点 | 本项目差异 |
|------|------|------|------------|
| 平台自带保存 | 官方、稳定 | 有水印、画质受限、无桌面批量 | 三平台统一、任务化、可配置画质 |
| 第三方解析站 | 免安装、快 | 广告、隐私风险、无任务管理、频繁失效 | 自托管、无广告、链接不外泄 |
| yt-dlp CLI | 强大、站点多 | 需命令行、无 UI、无任务中心 | 图形化 + 任务中心；yt-dlp 作为可选兜底 |
| 浏览器插件 | 一键 | 权限大、易被封、移动端不可用 | 服务端解析，跨设备可用 |
